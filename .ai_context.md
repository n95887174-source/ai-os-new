# AI Agent Context — Super-Agents OS v2.3

This project is a **deterministic, event-sourced LLM inference control plane**.

---

## 🧠 Core Architecture

### Single Source of Truth
- **`src/core/Kernel.ts`** is the SSOT. All provider metrics (latency, reliability, stability, reputation, task matrix, traces), routing weights, and decision history live here.
- State mutations happen exclusively through the Kernel's **reducer** — never directly.
- The Kernel emits `kernel:updated` after every state change.

### Communication
- **All** inter-service and component–service communication MUST go through `src/core/events.ts` (EventBus).
- Never import a service directly into a component for reactive data — use the EventBus and hooks (`useChatStore`, `useKeyStore`).

### Storage
- `src/core/storage.ts` provides `StorageDriver` / `LocalStorageDriver`.
- `KeyService` uses it to persist API keys under `super_agents_api_keys`.
- **`src/types/metrics.ts`** defines the schema for extended analytics (Latency Breakdown, Quality, Stability).

## 📡 EventBus Cheat Sheet

| Event | Payload | Description |
|-------|---------|-------------|
| `KEYS_LOADED` | `ApiKey[]` | Emitted on any key list change |
| `KEY_ADDED` | `Omit<ApiKey, 'id'\|'stats'>` | Triggers key creation in KeyService |
| `KEY_REMOVED` | `string (id)` | Triggers key removal |
| `CHECK_HEALTH` | `string (id)` | Triggers health check for one key |
| `CHECK_ALL_HEALTH` | `undefined` | Triggers health check for all keys |
| `SEND_MESSAGE` | `ChatRequest` | Initiates a chat request |
| `MESSAGE_RESPONSE` | `ChatResponse` | Chat result / error response |
| `chat:stream:start` | `{requestId, provider}` | Stream opened |
| `chat:stream:chunk` | `{requestId, chunk, provider}` | Incremental token |
| `chat:stream:end` | `{requestId, provider, latency, ttft, fullContent}` | Stream done |
| `chat:stream:error` | `{requestId, provider, error}` | Stream error |
| `NOTIFICATION` | `{message, type}` | Global notification toast |
| `kernel:updated` | `SystemState` | Kernel emits after every state change |

## 🛣️ Routing Strategies

`RouterService` supports: `broadcast`, `performance`, `reliability`, `latency`, `auto`, `race`, `smart`

- **`all-at-once`** (broadcast): Send to all active providers simultaneously.
- **`pick-one`** (single): Score-based selection (Bandit UCB1).
- **`auto`** (smart): Full Bandit routing — uses `kernel.getState()` metrics + adaptive weights.
- **`race`**: Send to top-N providers, use first response.

## ⚠️ Rules for AI Agents

### 1. TypeScript — `verbatimModuleSyntax` is ENABLED
```typescript
// ✅ CORRECT — types must use "import type"
import type { ApiKey } from '../services/KeyService';
import { keyService } from '../services/KeyService';

// ❌ WRONG — will cause TS1484 compile error
import { ApiKey, keyService } from '../services/KeyService';
```

### 2. CORS / Proxy
- Use `/proxy/openrouter`, `/proxy/nvidia` etc. for providers with CORS restrictions.
- See `vite.config.ts` for proxy targets. Gemini uses its native URL directly.

### 3. Error Handling
- Monitor HTTP `402` / `429`. On these errors, `KeyService.handleProviderError()` must be called.
- The Kernel will automatically reduce the reliability score of the offending provider.

### 4. Stats Recording
- After every successful response: call `keyService.recordUsage(provider, latency, tokens, model, { ttft, tps, task, experimentId, region })`.
- `task` should be granular (e.g., `code:debug`, `qa:reasoning`).
- `ttft` and `tps` are critical for the Extended Analytics engine.

### 5. SLA Enforcement
- Check `activeSLA` in key stats before selecting a provider.
- Honor `rules.slaThresholds` for automated circuit breaking.

### 5. Kernel Safety Contract
- Never write to Kernel state directly.
- The Kernel enforces invariants automatically (weight normalization, reliability floor, drift clamping).

### 6. UI Hardening
- Always use optional chaining (`?.`) for `stats` and `stats.extended` on `ApiKey` objects — legacy keys or freshly added keys will have these fields initialized to defaults, but defensive coding is required.
