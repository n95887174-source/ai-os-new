## 🚀 Эволюция: 5 фаз

### Фаза 1: Наблюдаемость и диагностика (1-2 недели)

**Проблема**: Когда что-то ломается — сложно понять где. Circuit breaker открылся, но почему? Rate limit ударил, но какой именно? Запрос ушёл в fallback, но на какой ключ?

**1.1 Request Tracing — сквозной трейс запроса**

Сейчас `MetricsDecorator` считает агрегаты, но нет **индивидуального трейса**:

```typescript
export interface RequestTrace {
  id: string;                    // correlation ID
  timestamp: number;
  prompt: string;                // первые 100 символов
  // Pipeline
  route: {
    strategy: RoutingStrategy;
    selectedProvider: string;
    selectedModel: string;
    selectedKeyId: string;
    scores: ScoringComponents[];  // все скоры маршрутизации
    skippedKeys: SkippedKeyEntry[];
    decisionOrigin: DecisionOrigin;
  };
  // Execution
  decorators: {
    rateLimit: { passed: boolean; bucketLevel: number };
    circuitBreaker: { state: 'closed' | 'open' | 'half-open'; probeAllowed: boolean };
    queue: { waitMs: number; priority: string; queueDepth: number };
    retry: { attempts: number; backoffs: number[] };
    cache: { hit: boolean; key?: string; similarity?: number };
  };
  // Result
  result: {
    latencyMs: number;
    ttftMs: number;
    tokensIn: number;
    tokensOut: number;
    cost: number;
    finishReason: string;
    fallbackUsed: boolean;
    fallbackFrom?: string;
  };
  error?: { code: string; message: string; provider: string };
}
```

UI: Вкладка «Traces» в ProviderManager — фильтры по провайдеру/модели/ошибке, timeline, drill-down в каждый запрос. Это **самая востребованная** фича для отладки.

**1.2 Real-time Provider Dashboard**

Сейчас метрики — это числа в таблице. Нужен живой дашборд:

- **Latency Sparkline** — мини-график TTFT/TPS за последние 30 минут (как в Grafana)
- **Circuit Breaker Status** — визуально: 🟢 closed / 🟡 half-open / 🔴 open с таймером до следующего probe
- **Rate Limiter Bucket** — прогресс-бар «30/60 RPM remaining»
- **Queue Depth** — сколько запросов ждут в priority queue
- **Cost Counter** — тикер как в такси, реальное время

**1.3 Provider Health Timeline**

`ProviderTracker` хранит EWMA, но нет **истории событий**. Добавить:

```typescript
interface HealthEvent {
  timestamp: number;
  type: 'latency_spike' | 'error_burst' | 'circuit_open' | 'circuit_close' | 
        'rate_limit' | 'quota_warning' | 'recovery' | 'key_rotated' | 'fallback';
  severity: 'info' | 'warning' | 'critical';
  details: Record<string, unknown>;
}
```

Отображать как timeline (как GitHub commit history) — когда и почему провайдер деградировал.

### Фаза 2: Умная маршрутизация 2.0 (2-3 недели)

**2.1 Semantic Routing — маршрутизация по содержимому**

У тебя уже есть `SemanticRouterDecorator` (маршрутирует simple/complex), но это примитивный эвристический подход. Нужна **настоящая семантическая маршрутизация**:

```typescript
export interface SemanticRouteRule {
  name: string;
  condition: {
    // Классификация промпта
    intent?: 'code' | 'creative' | 'factual' | 'math' | 'reasoning' | 'conversation';
    language?: 'en' | 'ru' | 'auto';  // язык промпта
    complexity?: 'simple' | 'medium' | 'complex';
    safetyLevel?: 'safe' | 'sensitive' | 'dangerous';
  };
  target: {
    provider: string;   // лучший провайдер для этого типа
    model?: string;     // конкретная модель
    temperature?: number;
    maxTokens?: number;
  };
  fallback?: SemanticRouteRule;  // если основной недоступен
}
```

Примеры:
- **Code prompt** → Groq/Cerebras (быстрый inference) или DeepSeek (код-специфичный)
- **Creative writing** → Gemini Pro / GPT-4o (лучшее качество)
- **Русский язык** → Yandex GPT / GigaChat (если доступны), иначе Gemini
- **Math/reasoning** → o1 / DeepSeek-Reasoner
- **Embedding/semantic** → только конкретные модели

**2.2 Multi-Provider Racing с Early Return**

Стратегия `race` уже есть в `RouterService`, но она не интегрирована с decorator stack. Нужен **настоящий parallel racing**:

```typescript
export interface RaceConfig {
  providers: string[];        // какие провайдеры участвуют
  mode: 'first_response' | 'best_quality' | 'consensus';
  timeoutMs: number;         // максимальное ожидание
  earlyReturnThreshold: number; // если TTFT < threshold, сразу вернуть
}

// first_response — кто первый ответил, того и используем (для low-latency)
// best_quality — ждать все, выбрать лучшего по оценке
// consensus — ждать 2+ совпадающих ответа, вернуть консенсус
```

**2.3 Adaptive Weight Tuning — самообучение маршрутизатора**

Сейчас веса маршрутизации (TTFT/TPS/reliability) — ручные. A/B тесты — ручные. Нужен **UCB1 с Contextual Bandits**:

```typescript
export interface ContextualBanditRouter {
  // Фичи контекста
  features: {
    hourOfDay: number;      // время суток (день/ночь — разная нагрузка)
    dayOfWeek: number;      // будни/выходные
    promptComplexity: number; // 0-1
    promptLanguage: string;
    recentErrorRate: number; // скользящее окно ошибок
    currentLoad: number;    // текущая нагрузка на систему
  };
  // Автоматическая корректировка весов
  updateWeights(reward: { success: boolean; latency: number; quality: number }): void;
}
```

Система сама учится: «в воскресенье ночью Groq быстрее, а в понедельник утром Gemini стабильнее».

### Фаза 3: Cost Intelligence (2 недели)

**3.1 Real-Time Cost Analytics**

У тебя есть `PricingService` с 40+ моделями и `CostManagerDecorator`, но нет **аналитики**. Нужен дашборд:

- **Cost by Provider** — pie chart + trend line
- **Cost by Model** — какие модели жрут бюджет
- **Cost by Agent** — какой агент (debate, chat, SRE) тратит больше
- **Cost Forecast** — линейная регрессия: «при текущем темпе ты потратишь $X к концу месяца»
- **Cost Anomaly Detection** — «сегодня расход на 3x выше обычного»

**3.2 Smart Model Downgrade Cascade**

У тебя есть `downgradeChain` в RoutingPolicyService. Расширить:

```typescript
export interface DowngradeStrategy {
  // Если latency > 5s, переключить на более быструю модель
  latencyThresholds: Array<{ maxMs: number; targetModel: string }>;
  // Если cost/1K tokens > $X, предложить альтернативу
  costThresholds: Array<{ maxPer1k: number; alternatives: string[] }>;
  // Если quota > 80%, перейти на запасной провайдер
  quotaThresholds: Array<{ pct: number; fallbackProvider: string }>;
  // Автоматическое переключение при circuit open
  circuitBreakerDowngrade: boolean;
}
```

Пример: GPT-4o → Gemini Flash → Groq Llama (при деградации)

**3.3 Budget Sandbox — «что если»**

Before-you-send превью:
- «Этот запрос будет стоить ~$0.003 (Gemini Flash) или ~$0.05 (GPT-4o)»
- «С текущим бюджетом ты можешь отправить ещё ~1,500 запросов на Flash»
- «Переключение на DeepSeek сэкономит $X/месяц при том же объёме»

### Фаза 4: Provider Lifecycle Automation (2-3 недели)

**4.1 Auto-Discovery — авторегистрация провайдеров**

Сейчас ключи добавляются вручную. Что если:

```typescript
export interface ProviderDiscovery {
  // Сканирует known endpoints на доступность
  discoverProviders(): Promise<DiscoveredProvider[]>;
  // Проверяет free tier доступность
  probeFreeTier(provider: string): Promise<FreeTierInfo>;
  // Автоматически добавляет ключ при вставке в буфер обмена
  autoDetectKey(keyText: string): { provider: string; valid: boolean } | null;
}
```

- Вставил `sk-...` → система определила «это OpenAI ключ» → предложила добавить
- Вставил `AIza...` → «Gemini ключ» → автозаполнение
- Вставил `cf-...` → «Cloudflare» → распарсила accountId

**4.2 Key Rotation & Lifecycle**

```typescript
export interface KeyLifecycleManager {
  // Автоматическая ротация при auth failure
  autoRotateOnAuthFail(keyId: string): void;
  // Пробация: новый ключ тестируется на small requests
  probationPeriod(keyId: string): Promise<boolean>;
  // Graceful degradation: не отключать ключ сразу при ошибке
  softDisable(keyId: string, reason: string): void;
  // Авто-восстановление: retry через N минут
  autoRecovery(keyId: string, backoffMs: number): void;
}
```

Сейчас ключ при ошибке переключается в `error` и всё. Нужен **lifecycle**: active → probation → degraded → quarantined → recovering → active

**4.3 Multi-Account Pool Management**

`GroupManager` + `KeyPoolSelector` — базовый пулинг. Расширить:

- **Account Groups**: «Рабочие аккаунты», «Личные», «Free tier»
- **Burst Capacity**: при spike нагрузки — автоматически подключить dormant ключи
- **Cross-Provider Pooling**: «Мне нужны 100 RPM» → распределить между 3 провайдерами
- **Quota Sharing**: если у Gemini quota исчерпана, направить на Groq

```typescript
export interface ProviderPlugin {

Это позволит:
- Добавлять новых провайдеров **без изменения кода** (через конфиг)
- Community-плагины: «Yandex GPT Provider Plugin»
- A/B тестировать нового провайдера до интеграции

Превратить AI-OS в **API gateway** для других приложений:

```

                                     rate limiting, cost control

Любое приложение может использовать AI-OS как единый entry point к 20+ провайдерам с автоматической маршрутизацией, fallback и бюджетированием.

## 🎯 Моё мнение

Самое поразительное — **глубина стека декораторов**. 11 декораторов, собранных в pipeline через `AdapterFactory` — это production-grade архитектура. Circuit Breaker, Priority Queue, Semantic Cache, Canary Router — это не «pet project», это real-world infrastructure.

**Но есть разрыв**: под капотом — Ferrari, а на приборной панели — спидометр от Жигулей. Таблица с ключами, числа в колонках, нет графиков, нет трейсов, нет живых данных.

Мой главный совет: **Request Tracing + Real-time Dashboard**. Когда ты сможешь кликнуть на запрос и увидеть весь путь (routing decision → circuit breaker → queue → retry → cache → latency breakdown) — это полностью меняет опыт отладки. Ты перестанешь гадать «почему ответ пришёл через 15 секунд» и начнёшь видеть «queue wait 12s → circuit breaker was open → fallback to Groq → 2s response».

Второе — **Semantic Routing**. Сейчас маршрутизация базируется на метриках (latency, TPS, reliability), но не на **содержимом запроса**. А разница между «напиши стих» и «дебажь этот код» — это разница между Gemini Pro и Groq Llama. Один и тот же провайдер не оптимален для всех типов задач.
