## 🎯 Спецификация тестовых кнопок (по запросу)

**Концепция: "Provider Health Check" панель в ChatPanel:**

```
┌─────────────────────────────────────────────────┐
│ 🔬 Provider Health Check                         │
│                                                  │
│ [Test All Keys]  (прогресс: ████████░░ 3/7)     │
│                                                  │
│ ✅ Groq       ● llama-3.3-70b   320ms  "Hello!" │
│ ✅ Gemini     ● gemini-2.0-flash 450ms  "Hello!" │
│ ❌ OpenRouter ● —                timeout         │
│ ✅ NVIDIA     ● meta/llama3     890ms  "Hello!" │
│ ⏳ Mistral    ● —                тестируется...  │
│                                                  │
│ 🟢 4 keys готовы к диалогу                       │
│ 🔴 1 key не отвечает (OpenRouter)                │
│                                                  │
│ [Send Test: "What is AI?"] [Custom...]           │
└─────────────────────────────────────────────────┘
```

**Логика:**
- **Авто-подбор модели**: для каждого ключа запрашивает `getAvailableModels()` → берёт первую (самую быструю)
- **Отправка теста**: эмитит `EVENTS.SEND_MESSAGE` как parallel broadcast, но с флагом `testMode: true`
- **ChatService** в test-mode: не сохраняет в историю, не пишет в memory, не триггерит RAG
- **Результат**: `chat:test:result { keyId, provider, model, status, latency, preview }`
- **Статус "готов к диалогу"**: если latency < 5000ms и response не пустой — зелёный
- **Повторный тест**: кнопка ретеста для отдельных ключей
- **История тестов**: сохраняется в `key.tests[]` или отдельную таблицу
