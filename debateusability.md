## 🔍 Анализ верстки и юзабилити дебатов

### ❌ Критические проблемы юзабилити

**1. Монстр-компонент DebatePanel — 865 строк в одном файле**
Это не компонент, а приложение. 20+ state-переменных, 6 логических секций (setup, active debate, history, analytics, probe, auto-debate). Невозможно тестировать, рефакторить и поддерживать. Любое изменение ломает соседнюю логику.

**2. Два отдельных маршрута для одной и той же функциональности**
`/debate` → DebatePanel, `/debate-runtime` → DebateRuntimePanel. Пользователь не понимает, в чём разница. Обе панели делают одно и то же (создают дебаты, показывают аргументы), но с разными UX:

- **DebatePanel**: классический чат-формат, есть история, probe, auto-debate, инъекция аргументов
- **DebateRuntimePanel**: топологии, cognitive pressure, бюджет, сессии — но НЕТ чата аргументов

Пользователю нужно прыгать между двумя вкладками, чтобы получить полный опыт.

**3. Нет просмотра аргументов в DebateRuntimePanel**
Самая критичная дыра — RuntimePanel показывает сессии, топологии, agent states, cognitive metrics, но **не показывает сами аргументы!** Пользователь запускает дебат и видит только «thinking», «streaming» статусы, но не может прочитать, что агенты говорят.

**4. Setup-скрин перегружен**
DebatePanel: thesis → strategy → max rounds → temperature → archetype → agents → constraints → probe → start → auto-debate. Это **10+ шагов** на одном экране. Для нового пользователя — это стена конфигурации.

---

### 🟠 Серьёзные UX-проблемы

**5. Нет persistent-сессий в DebateRuntimePanel**
Сессии теряются при перезагрузке страницы. DebatePanel хотя бы сохраняет историю через Dexie/localStorage.

**6. History показывает только 6 аргументов**
`h.arguments.slice(-6)` — даже в развёрнутом виде видно лишь последние 6 из 30-50 аргументов. «+N more arguments» — не кликабельно.

**7. Нет разницы между «pro» и «con» визуально в чате**
Аргументы различаются только цветом (4 цвета, циклично). `arg.position` (pro/con/neutral) не используется для визуального разделения. Пользователь не может быстро понять, кто за, кто против.

**8. Constraint-секция — микро-шрифты, без контекста**
Строка 597-612: `fontSize: '0.78rem'`, select `fontSize: '0.7rem'`, `minWidth: 140` — на мобильном это нечитаемо. Нет описания, что означает каждый constraint.

**9. Probe-результаты — spaghetti-код**
Строки 648-692: вложенные тернарники, микро-размеры (`fontSize: 0.72rem, 0.7rem, 0.6rem`), нет визуальной иерархии. Сложно понять, кто готов к дебату, а кто нет.

**10. Нет фильтрации/поиска по аргументам**
В активном дебате с 50+ аргументами — только scroll. Нет фильтра по агенту, раунду, confidence.

---

### 🟡 Проблемы верстки

**11. Inline styles everywhere — невозможно темизировать и поддерживать**
1207 строк, ~95% стилей inline. Нет CSS modules, нет Tailwind. Изменение дизайна = grep по всему файлу.

**12. Проблема с responsive**

- `gridTemplateColumns: session ? '1fr 380px' : '1fr'` — на экранах <1024px sidebar уходит за край
- Agent grid `minmax(220px, 1fr)` — на мобильном слишком широко
- Нет медиа-запросов

**13. Sidebar аналитики скроллится отдельно от основного контента**
`overflowY: 'auto'` на sidebar — при длинной аналитике пользователь видит либо чат, либо метрики, но не оба.

**14. PhaseTimeline — неинформативный**
7 точек 8x8px без подписей. Пользователь не понимает, какая фаза за какой следует.
