## Audit Methodology

Each failure class was audited using:

1. **Automated grep across `src/kernel/services/`**, `src/stores/`, `src/llm/`, `src/components/`
2. **Code review of 60+ files** across all failure classes
3. **Historical context** from Sessions 1-31 (pre-existing fixes tracked)
4. **Pattern analysis** — existing protections (locks, dedup sets, validators) vs gaps

### Detection types:

- **🔍 Static** — TypeScript type checks, ESLint rules, runtime validators
- **🔍 Runtime** — try/catch, guard clauses, state checks, WAL recovery
- **🔍 Architectural** — DI lifecycle, contract interfaces, event schemas
- **🚫 None** — no mechanism to detect this failure class
