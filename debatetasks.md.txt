# 1. Что у Poe происходит концептуально

Когда ты меняешь модель посреди диалога, это не “переключение мозга”.

Обычно это выглядит так:

```text
Conversation State
   ├── messages
   ├── attachments
   ├── memory
   ├── metadata
   └── execution context

        ↓

Model Adapter
   ├── GPT
   ├── Claude
   ├── Gemini
   └── Local agent
```

То есть:

**чат принадлежит не модели, а session runtime.**

Модель — просто исполнитель.

Это ключевая идея.

# 3. Как устроить переключение модели “как Poe”

Сейчас у большинства самодельных систем это так:

```text
chat -> fixed model
```

Нужно сделать:

```text
chat -> agent binding
agent -> provider binding
```

Пример:

```json
{
  "agent": "coder",
  "provider": "minimax"
}
```

Потом во время сессии:

```json
{
  "agent": "coder",
  "provider": "gpt"
}
```

История остаётся у Session.

Меняется только executor.

# 4. Как добавить настоящий parallel execution

Это сердце системы.

Нужен **Task Scheduler**.

---

## Sequential (как сейчас)

```text
Task A
 ↓
Task B
 ↓
Task C
```

---

## Parallel DAG

```text
          Root Task
         /    |    \
        A     B     C
       / \         / \
      D   E       F   G
```

Каждый узел — отдельный агент-run.

---

Scheduler должен:

### создавать задачи

```ts
createTask()
```

### назначать исполнителя

```ts
assignAgent()
```

### запускать параллельно

```ts
Promise.all(...)
```

### собирать результат

```ts
merge()
```
