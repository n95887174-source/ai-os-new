## 🔥 Конкретные улучшения по каждому файлу (сортировка по критичности)

### 1. `src/kernel/instances.ts` (92 импорта) — **самое горячее место**

**Проблема:** любой тест или изолированный модуль тянет за собой всё ядро. Медленные сборки, сложно мокать.

**Что сделать:**
- Разделить на **три отдельных файла**, экспортируемых через баррел:
  - `instances-core.ts` – только базовые сервисы (EventBus, Logger, Config)
  - `instances-services.ts` – KeyService, RouterService, PolicyService...
  - `instances-ui.ts` – сторы, хелперы для UI
- Внедрить **ленивую инициализацию** через фабрики: `getKeyService()` вместо `export const keyService = new KeyService()`. Тогда импорт `instances` не запускает создание всех сервисов.
- Добавить **Symbol-ключи** для DI, чтобы можно было заменять реализации в тестах.

```ts
// Было: export const keyService = new KeyService(eventBus, config)
// Стало: export const getKeyService = memoize(() => new KeyService(getEventBus(), getConfig()))
```

### 2. `src/kernel/event-bus.ts` + `event-names.ts`

**Проблема:** события — строки. Нет типизации payload'ов. Легко опечататься.

**Что сделать:**
- Перевести на **типизированный EventBus** с discriminated union:

```ts
type EventMap = {
  'key:added': { keyId: string; provider: string }
  'key:quota:exceeded': { keyId: string; limit: number }
  // ... 155 штук
}
type TypedEventBus = {
  emit<K extends keyof EventMap>(event: K, payload: EventMap[K]): void
  on<K extends keyof EventMap>(event: K, handler: (payload: EventMap[K]) => void): void
}
```

- **Автогенерация имён** из констант → не будет рассинхрона.

### 3. `src/kernel/kernel.ts` (SystemKernel)

**Проблема:** скорее всего, машина состояний с кучей `if (state === 'starting') ...`. Трудно тестировать и расширять.

**Что сделать:**
- Выделить **XState** или собственную реализацию с конечным числом состояний и явными переходами:

```ts
type KernelState = 'uninitialized' | 'booting' | 'running' | 'shuttingDown' | 'halted'
type KernelEvent = { type: 'BOOT_COMPLETE' } | { type: 'SHUTDOWN' } | ...
```

- Перенести side effects (запуск сервисов, остановка) в **акторы** или отдельные middleware.

### 4. `src/kernel/services/config-registry.ts` (51 импорт)

**Проблема:** глубоко замороженный объект. Чтобы изменить конфиг (например, через UI Settings), приходится перезагружать всё приложение.

**Что сделать:**
- Сделать **реактивный конфиг** (Zustand или observable). При изменении — сервисы, которые подписались на конкретные ключи, обновляются.
- Разделить на **runtime config** (меняется без перезагрузки) и **build-time config** (переменные окружения).
- Добавить валидацию схемы (Zod) → при старте проверять, что все обязательные ключи есть.

### 5. `src/kernel/container.ts` (DI-контейнер)

**Проблема:** вероятно, самодельный или слишком простой (просто Map). Нет lifecycle-управления (singleton/scoped/transient).

**Что сделать:**
- Внедрить **InversifyJS** или **TSyringe**. Они дают декораторы `@injectable`, автоматическое разрешение зависимостей, области видимости.
- Если самодельный — добавить **валидацию циклических зависимостей** (утилита `madge` или своя).

### 6. `src/kernel/bootstrap.ts`

**Проблема:** фазы инициализации (`init → start`) наверняка выполняются последовательно, но нет отката при ошибке в середине.

**Что сделать:**
- Реализовать **транзакционную инициализацию**: каждая фаза может закоммитить или откатить изменения.
- Добавить **таймауты** на каждую фазу (если сервис не стартовал за 5 сек — переходим в degraded mode).

## 🛠️ Инструменты, которые спасут жизнь при 1000+ файлов

1. **`depcheck`** — найдёт неиспользуемые зависимости.
2. **`madge`** — построит граф зависимостей и покажет циклы.
3. **`knip`** (более мощный) — наймёт мёртвый код и экспорты.
4. **ESLint plugin `import`** с правилами:
   - `no-cycle` — запретить циклические импорты
   - `no-relative-parent-imports` — заставить использовать алиасы (`@kernel/...`)
5. **TypeScript project references** — разбить на подпроекты (kernel, ui, llm, shared), ускорить сборку.
