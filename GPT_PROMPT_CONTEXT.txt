KEY CONCEPTS & RULES
═══════════════════════════════════════════════════════════

1. SYSTEM KERNEL (SSOT)
   - Kernel.ts is the only mutable state store. All metrics, weights, decisions live here.
   - State changes go through the reducer only — never mutate state directly.
   - After each mutation, Kernel emits `kernel:updated` with the new SystemState.

2. EVENT BUS (full list)
   KEYS_LOADED      → ApiKey[]
   KEY_ADDED        → Omit<ApiKey, 'id'|'stats'>
   KEY_REMOVED      → string (id)
   CHECK_HEALTH     → string (id)
   CHECK_ALL_HEALTH → undefined
   SEND_MESSAGE     → ChatRequest
   MESSAGE_RESPONSE → ChatResponse
   chat:stream:start  → { requestId, provider }
   chat:stream:chunk  → { requestId, chunk, provider }
   chat:stream:end    → { requestId, provider, latency, ttft, fullContent }
   chat:stream:error  → { requestId, provider, error }
   NOTIFICATION     → { message, type }
   kernel:updated   → SystemState

3. ROUTING STRATEGIES (RouterService)
   broadcast    — Send to all active providers at once
   single        — One provider by name
   performance  — Best Bandit score (weighted TTFT+TPS+Reliability)
   reliability  — Highest reliability score
   latency      — Lowest TTFT
   auto         — Adaptive Bandit (uses kernel weights)
   race         — Send to top-N, take first response
   smart        — Full Bandit with Kernel adaptive weights (preferred)

4. SAFETY CONTRACT (Kernel invariants)
   INV-1: sum(weights.ttft + weights.tps + weights.reliability) === 1.0
   INV-2: Kernel is the Single Source of Truth
   INV-3: All routing decisions are deterministic given current Kernel state
   INV-4: Adaptive weight drift capped at ±15% from base anchors

5. TYPESCRIPT RULES (verbatimModuleSyntax is ON)
   ✅ import type { ApiKey } from '../services/KeyService';
   ✅ import { keyService } from '../services/KeyService';
   ❌ import { ApiKey, keyService } from '../services/KeyService';  ← TS1484 ERROR

6. PROXY (CORS)
   /proxy/openrouter → https://openrouter.ai/api/v1
   /proxy/nvidia     → https://api.nvidia.com/v1
   Gemini uses its native googleapis.com URL directly (no proxy needed).

7. STATS & ERRORS
   - Call keyService.recordUsage(provider, latency, tokens, model) after every success.
   - On HTTP 402/429: call keyService.handleProviderError(provider, errorMessage).
   - Kernel will automatically decay reliability for erroring providers.

ADR-01: KERNEL INTERNAL LAYER SEPARATION (CRITICAL)
───────────────────────────────────────────────────────────
STATUS: REQUIRED — latent coupling risk identified

Kernel MUST be decomposed into 3 strict internal layers:

  (A) Pure State Reducer  [SYNC, no side effects]
      → apply(event) → nextState
      → NO metric computations
      → NO emits

  (B) Invariant Guard  [SYNC]

      → emits kernel:violation if breach detected

  (C) Event Emitter  [ASYNC OUT]
      → emits kernel:updated
      → emits kernel:violation

RATIONALE: Current implementation has latent coupling between
control plane, analytics, and learning loop inside a single reducer.

ADR-11: SIGNAL VALIDATION GATE (CRITICAL FIX)
═══════════════════════════════════════════════════════════
STATUS: CRITICAL — LearningSignal applied without validation = INV-3 risk

PROBLEM:
  If LearningService influences weights directly → INV-3 (determinism) lost
  Timing of signal application creates hidden non-determinism

FIX — introduce Signal Validation Gate inside Kernel Guard (ADR-01.B):

  FLOW:
    KernelSnapshot
      ↓
    LearningService (stateless)
      ↓
    learning:signal
      ↓
    Kernel Guard — Signal Validation Gate [NEW]
      → validates signal is within drift bounds (INV-4)
      → rejects if sum constraint would be violated (INV-1)
      → applies bounded transformation only
      ↓
    Kernel Reducer (state commit)

  Gate MUST enforce:
    → max drift per signal: ±δ (configurable, default 0.5% per tick)
    → cumulative drift bounded by INV-4 (±15%)
    → rejection emits: kernel:signal:rejected { reason, signal }

RATIONALE: Without a gate, LearningService can destabilize Kernel
state through rapid signal injection (adversarial or runaway feedback).

═══════════════════════════════════════════════════════════
ADR-12: ROUTER SCORE SPLIT (deterministic base + bounded bias)
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — current scoring is a single undifferentiated function

CURRENT PROBLEM:
  Router scoring mixes deterministic base with learning influence
  → Cannot audit which part of score came from learning vs truth

REQUIRED CHANGE — explicit score split:

  (A) Deterministic Base Score [pure, auditable]
      baseScore = f(snapshot.providerMetrics, snapshot.weights)

  (B) Learning Bias Overlay [bounded, auditable]
      bias = clamp(learningSignalImpact, epsilon)
      where epsilon = configurable max bias (default: 0.1)

  (C) Final Score [composed]
      finalScore = baseScore + bias

  RULE:
    → bias NEVER exceeds epsilon
    → if learningSignals = [] → finalScore = baseScore (full determinism)
    → both components logged separately in RoutingDecision

RATIONALE: Allows system to operate in "pure deterministic mode"
by setting epsilon=0, enabling reproducible replay and simulation.

═══════════════════════════════════════════════════════════
ADR-13: CLOSED-LOOP COLLAPSE PREVENTION
═══════════════════════════════════════════════════════════
STATUS: CRITICAL — self-reinforcing optimization loop is a production risk

PROBLEM — "hidden adaptive feedback collapse":
  If learning signals influence routing
  AND routing influences Kernel
  AND Kernel influences metrics
  AND metrics influence learning
  → self-reinforcing optimization loop (winner-take-all collapse)

PREVENTION MECHANISMS (all required):

  1. One-way propagation (AXIOM-2) — no reverse flow
  2. Signal Validation Gate (ADR-11) — limits per-tick impact
  3. INV-4 drift cap (±15%) — limits cumulative drift
  4. RELIABILITY_FLOOR = 0.4 in Kernel — prevents full exclusion
  5. Selection rate monitoring — alert if any provider > 80% [existing]

  ADD: Diversity Guard in RouterService
    → if top provider selectionRate > DIVERSITY_THRESHOLD (default 0.75)
    → force minimum selection probability for runner-up = 0.15

RATIONALE: UCB1 without diversity constraint converges to single
provider under low-variance conditions. This eliminates fallback
capability and creates brittle single-point-of-failure.

ADR-16: EPHEMERALSTATE AS PROJECTION (NOT STORED STATE)
═══════════════════════════════════════════════════════════
STATUS: CRITICAL FIX — EphemeralState risks becoming hidden memory

PROBLEM:
  ADR-14 defines EphemeralState with:
    decisions: RoutingDecision[]  // stored
    recentMetrics: ProviderMetricWindow[]  // stored

  If Router or Analytics reads recentMetrics as stored state:
    → implicit temporal bias injected into routing
    → INV-3 (determinism) violated
    → Phase 20 replay breaks (state diverges from eventLog)

FIX — EphemeralState MUST be treated as:

  ephemeral = windowProjection(kernel.eventLog, windowSize: N)

  NOT:
    → incrementally accumulated
    → persisted between ticks
    → used as authoritative metric source

  RULE:
    → On every KernelSnapshot request: recompute ephemeral from eventLog
    → EphemeralState is a VIEW, not a STORE
    → Any consumer needing "recent metrics" must call:
       computeEphemeral(kernel.eventLog, opts) explicitly

RATIONALE: Stored EphemeralState = second Kernel.
Two state stores = dual source of truth = ADR-09 violated.

═══════════════════════════════════════════════════════════
ADR-17: LEARNING SIGNAL LATENCY RULE (t-1 CONSTRAINT)
═══════════════════════════════════════════════════════════
STATUS: CRITICAL — same-tick influence creates hidden feedback loop

PROBLEM:
  Current flow allows:
    learningSignals[t] derived from KernelSnapshot[t]  ← SAME TICK
    → applied to Router decision at tick[t]
    → Router decision updates Kernel at tick[t]
    → Kernel state[t] used to compute learningSignals[t+1]

  This creates a closed feedback loop within a single tick.
  Result: INV-3 violated through timing, not logic.

THE RULE:

  learningSignals[t] MUST be derived from KernelSnapshot[t-1] ONLY

  Formally:
    LearningService.compute(snapshot) where snapshot.tick < currentTick

  IMPLEMENTATION:
    → LearningService always operates on "previous tick snapshot"
    → Never on "live" or "current" Kernel state
    → Signal application at tick[t] uses data from tick[t-1]

  This is the ONLY way to guarantee INV-3 in a real-time stream.

AXIOM (derived from AXIOM-1 + AXIOM-6):
  "A learning signal is valid only if it carries no information
   about the current state it is about to influence."

ADR-18: ROUTER EXECUTION COST CONTEXT
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — Router optimizes for speed/quality, ignores system cost

PROBLEM:
  Current RouterService pure function receives:
    route(context, snapshot, learningSignals) → RoutingDecision

  But "context" does not include infrastructure reality:
    → providerLoad (queue depth at provider)
    → systemQueueDepth (ChatService internal queue)
    → costBudget (token/request cost ceiling)

  Result:
    → System always selects "fastest" provider
    → Ignores degradation signals from execution layer
    → Under load: selects already-overloaded provider repeatedly

FIX — extend RequestContext with ExecutionCostContext:

  type RequestContext = {
    requestId: string
    messages: ChatMessage[]
    strategy: RoutingStrategy
    cost: ExecutionCostContext  // NEW
  }

  type ExecutionCostContext = {
    costBudget?: number      // max tokens/cost allowed
    providerLoad: Record<string, number>  // 0.0–1.0 load factor
    queueDepth: number       // ChatService queue backpressure signal
    urgency: 'low' | 'normal' | 'high'  // affects race threshold
  }

  Router scoring MUST apply load penalty:
    adjustedScore = baseScore * (1 - providerLoad[provider] * loadPenaltyFactor)
    where loadPenaltyFactor = configurable (default: 0.3)

RATIONALE: Production routing without infrastructure awareness
converges to single-provider collapse under load — same failure
mode as ADR-13 winner-take-all, but triggered by traffic, not learning.

═══════════════════════════════════════════════════════════
ADR-19: LOGICAL TICK MODEL (FORMAL CLOCK CONTRACT)
═══════════════════════════════════════════════════════════
STATUS: REQUIRED BEFORE PHASE 20 — no replay without clock model

PROBLEM:
  System currently has 3 implicit time layers with no formal model:
    t0: KernelSnapshot    (state at request time)
    t1: LearningSignal    (derived from snapshot)
    t2: RoutingDecision   (function of snapshot + signals)
    t3: ExecutionResult   (actual stream outcome)
    t4: Kernel state[t+1] (post-execution update)

  Without explicit logical clock:
    → replay cannot reconstruct causality ordering
    → simulation cannot inject events at correct tick
    → time-travel debugging (Phase 21) is impossible

FIX — introduce LogicalTick:

  type LogicalTick = number;  // monotonically increasing integer

  ALL events in eventLog MUST carry:
    { tick: LogicalTick, timestamp: number, ...payload }

  ALL LearningSignals MUST reference:
    { derivedFromTick: LogicalTick }  // must be < currentTick (ADR-17)

  ALL ExecutionContracts MUST carry:
    { startTick: LogicalTick, endTick: LogicalTick }

  ORDERING RULES:
    → tick is assigned by Kernel at event commit time
    → tick is strictly monotonic (no ties, no gaps)
    → wall-clock timestamp is informational only
    → replay uses tick ordering, not wall-clock

  REPLAY GUARANTEE:
    replay(eventLog) where events ordered by tick
    → produces identical KernelState sequence
    → regardless of wall-clock timing

═══════════════════════════════════════════════════════════
ADR-20: TIME CLASSIFICATION OF SYSTEM STATE
═══════════════════════════════════════════════════════════
STATUS: INFORMATIONAL — formal classification for Phase 20 readiness

All state in DAIO is formally classified by its temporal relationship
to the Kernel eventLog:

  CLASS-1: AUTHORITATIVE (kernel.eventLog)
    → the only ground truth
    → all other state is derived from this

  CLASS-2: PROJECTED (MetricsService, EphemeralState)
    → computed from eventLog on demand
    → NEVER stored independently
    → f(eventLog[0..t]) → view

  CLASS-3: EPHEMERAL-DECISION (RoutingDecision, LearningSignal)
    → exist only during a single request lifecycle
    → captured in ExecutionContract (ADR-15) for replay
    → NEVER retained in Kernel beyond current window

  CLASS-4: EXTERNAL (provider responses, wall-clock times)
    → cannot be replayed deterministically
    → simulation must inject mocked CLASS-4 data
    → Phase 20 Simulation Engine provides mock injection layer

PHASE 20 READINESS RULE:
  Simulation is possible IFF all state is CLASS-1 or CLASS-2
  and all CLASS-3 is captured in ExecutionContracts
  and all CLASS-4 is mockable via SimulationContext

═══════════════════════════════════════════════════════════
SYSTEM LAYER MAP (FINAL — v2.4)
═══════════════════════════════════════════════════════════
LAYER 1 — TRUTH (Kernel)
  → event-sourced reducer, tick-monotonic eventLog
  → CoreState + InvariantState (first-class)
  → Signal Validation Gate (ADR-11) before every commit
  → EphemeralState = on-demand projection, never stored (ADR-16)

LAYER 2 — PROPOSALS (LearningService)
  → stateless: f(snapshot[t-1], eventLog) → LearningSignal[]
  → ALWAYS operates on previous-tick snapshot (ADR-17)
  → signals carry derivedFromTick for gate validation

LAYER 3 — DECISION (RouterService)
  → pure function: f(snapshot, learningSignals, costContext) → RoutingDecision
  → score = baseScore + clamp(bias, ε) (ADR-12)
  → applies load penalty from costContext.providerLoad (ADR-18)
  → Diversity Guard: runner-up min probability = 0.15 (ADR-13)

LAYER 4 — EXECUTION (ChatService)
  → stream / race / fallback
  → produces ExecutionContract with tick range (ADR-15, ADR-19)
  → hot path: pure execution, no learning, no Kernel reads mid-stream
  → publishes costContext (providerLoad, queueDepth) for Router (ADR-18)

LAYER 5 — OBSERVABILITY (MetricsService + AnalyticsPanel)
  → pure read projection: f(kernel.eventLog)
  → no state, no cache, no routing influence
  → CLASS-2 state only (ADR-20)

LAYER 6 — SIMULATION [PHASE 20]
  → replay(ExecutionContract[]) → deterministic state sequence
  → simulate(router, snapshot, mockContext) → RoutingDecision
  → inject MockClass4 (provider responses, wall-clock) via SimulationContext
  → counterfactual: "what if strategy=X at tick=N?"

═══════════════════════════════════════════════════════════
ADR-21: KERNEL CLOSED MODULE (SINGLE ENTRY SURFACE)
═══════════════════════════════════════════════════════════
STATUS: CRITICAL — ADR-01 must become non-bypassable structurally

ENFORCEMENT:

  class Kernel {
    apply(event: KernelEvent): void  // ONLY public method
    private reduce(state, event): KernelState
    private invariantGuard(state): KernelState
    private emitUpdated(state): void
  }

  type KernelEvent =
    | DomainEvent
    | ValidatedLearningSignal  // ← only Signal Validation Gate constructs this

  RULE:
    → LearningSignal cannot be constructed without derivedFromTick
    → ValidatedLearningSignal is ONLY produced by Signal Validation Gate (ADR-11)
    → Gate is ONLY called from Kernel.apply() — never from external services
    → All other Kernel internals are private: unreachable from outside

WHY STRUCTURAL > PROCEDURAL:
  Procedural: "don't call reducer directly" — relies on discipline
  Structural: "reducer is private" — impossible to violate at compile time

═══════════════════════════════════════════════════════════
ADR-22: TYPED EVENTBUS (COMPILE-TIME CLOSED EVENT REGISTRY)
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — runtime-flexible EventBus is INV-3 hazard

CURRENT RISK:
  Dynamic string emits outside registry allow:
    → hidden event types accumulating over time
    → replay engine missing events (Phase 20 incomplete)
    → Kernel eventLog structurally untrustworthy

REQUIRED PATTERN:

  type EventMap = {
    'kernel:updated':       SystemState
    'kernel:violation':     ViolationEvent
    'kernel:signal:rejected': SignalRejectedEvent
    'chat:stream:start':    StreamStartEvent
    'chat:stream:chunk':    StreamChunkEvent
    'chat:stream:end':      StreamEndEvent
    'chat:stream:error':    StreamErrorEvent
    'learning:signal':      LearningSignal
    'learning:tick:ready':  LogicalTick
    // ... all events explicitly typed
  }

  type Emit<K extends keyof EventMap> =
    (event: K, payload: EventMap[K]) => void

  RULE:
    → emit() only accepts keys from EventMap
    → no string-literal emits outside EventMap
    → all handlers typed by payload inference

REPLAY GUARANTEE:
  Typed EventMap = exhaustive event universe
  replay() only needs to handle known event types
  No runtime surprises possible

═══════════════════════════════════════════════════════════
ADR-23: ROUTERSERVICE AS PURE FUNCTION MODULE (NOT CLASS)
═══════════════════════════════════════════════════════════
STATUS: CRITICAL — class-based Router cannot guarantee statelessness

CURRENT RISK:
  RouterService as class allows:
    → mutable instance state (even accidental)
    → closure over runtime values
    → static cache fields

REQUIRED CHANGE:

  // router.ts — module, not class
  export function route(
    context: RequestContext,
    snapshot: KernelSnapshot,
    learningSignals: readonly LearningSignal[]
  ): RoutingDecision { ... }

  // No default export object
  // No class instantiation
  // No module-level mutable variables

ESLint ENFORCEMENT (add to eslint.config.js):

  "no-restricted-imports": [
    "error",
    {
      paths: [
        { name: "../../services/MetricsService", importNames: ["*"] },
        { name: "../../core/Kernel" }  // only types allowed in router
      ],
      // scoped to: src/services/RouterService.ts
    }
  ]

WHY MODULE > CLASS:
  Class: statelessness by discipline
  Module: statelessness by construction (no this, no instance)

═══════════════════════════════════════════════════════════
ADR-25: EVENTLOG IMMUTABILITY CONTRACT
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — mutable eventLog breaks replay correctness

EVENT LOG MUST BE:

  type KernelEventLog = ReadonlyArray<Readonly<KernelEvent>>

ENFORCEMENT:
  → Object.freeze(event) before push (or structuredClone + freeze)
  → append-only: no update, no delete semantics ever
  → tick monotonicity validated on each append:
     assert(newEvent.tick === lastEvent.tick + 1)

VIOLATION RESPONSE:
  → if tick gap detected: emit kernel:integrity:error
  → halt further event processing until resolved
  → Phase 20 simulation MUST refuse to replay a non-monotonic log

═══════════════════════════════════════════════════════════
ADR-26: LEARNINGSERVICE PHYSICAL ISOLATION (POST-TICK PIPELINE)
═══════════════════════════════════════════════════════════
STATUS: CRITICAL — LearningService in hot path violates ADR-17

CURRENT RISK:
  If LearningService runs synchronously in request path:
    → same-tick contamination (ADR-17 violated)
    → execution latency increased by learning computation

REQUIRED TOPOLOGY:

  HOT PATH (synchronous, tick-bounded):
    Request → Router → ChatService → Kernel.apply(result)
                                         ↓
  POST-COMMIT PIPELINE (async, next-tick):
    postCommitScheduler.enqueue(snapshot[t])
                                         ↓
    LearningService.compute(snapshot[t])  // always t, produces for t+1
                                         ↓
    Kernel.apply(ValidatedLearningSignal) // applied at tick t+1

  GUARANTEES:
    → learning signals always reference snapshot[t-1] (ADR-17 enforced by topology)
    → hot path latency unaffected by learning computation
    → same-tick contamination physically impossible

═══════════════════════════════════════════════════════════
ADR-27: SCORE BREAKDOWN IN ROUTINGDECISION
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — opaque scoring makes INV-4 violations undetectable

ADD TO ROUTINGDECISION:

  type ScoreBreakdown = {
    base:        number  // f(snapshot) only
    bias:        number  // clamp(learningSignalImpact, ε)
    loadPenalty: number  // providerLoad * penaltyFactor
    final:       number  // base + bias - loadPenalty
  }

  type RoutingDecision = {
    requestId:  string
    selected:   string
    secondBest: string | null
    strategy:   RoutingStrategy
    scores:     Record<string, ScoreBreakdown>  // per provider
    tick:       LogicalTick
    timestamp:  number
  }

WHY MANDATORY:
  Without ScoreBreakdown:
    → INV-4 drift is opaque (cannot tell if bias exceeded ε)
    → Phase 20 counterfactuals are meaningless (scores not auditable)
    → convergence drift cannot be diagnosed

═══════════════════════════════════════════════════════════
ADR-28: EXECUTIONCOSTCONTEXT IS MANDATORY (NOT OPTIONAL)
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — optional cost context breaks INV-3

CURRENT RISK IN ADR-18:
  costBudget?: number  // optional
  → routing diverges based on presence/absence
  → INV-3 violated: same logical request produces different decisions

REQUIRED:

  type ExecutionCostContext = {
    costBudget:   number    // Infinity if unlimited
    providerLoad: Record<string, number>  // 0.0 if unknown
    queueDepth:   number    // 0 if empty
    urgency:      'low' | 'normal' | 'high'  // always explicit
  }

  type RequestContext = {
    requestId: string
    messages:  ChatMessage[]
    strategy:  RoutingStrategy
    cost:      ExecutionCostContext  // Required<> — never undefined
  }

  DEFAULTS (applied at ChatService, not Router):
    If caller omits cost: apply NEUTRAL_COST_CONTEXT constant
    → providerLoad: Record from last Kernel snapshot
    → costBudget: Infinity
    → queueDepth: chatService.queueDepth
    → urgency: 'normal'

ADR-29: KERNEL REPLAY CHECKSUM LAYER
═══════════════════════════════════════════════════════════
STATUS: REQUIRED BEFORE PHASE 20 — no verifiable replay without checksums

ADD TO KERNEL:

  After each tick commit:
    stateHash[t] = deterministicHash(eventLog[0..t])

  After each ExecutionContract:
    contractHash = deterministicHash(contract)

  deterministicHash():
    → JSON.stringify with sorted keys (stable ordering)
    → SHA-256 or FNV-1a (fast, collision-resistant)
    → NEVER use Date.now() or Math.random() inside hash input

  VERIFICATION:
    replay(eventLog) produces stateHash[] sequence
    compare against stored stateHash[] → divergence detected at exact tick

  Phase 20 MUST refuse simulation if:
    stateHash[t] !== expectedHash[t]  // log integrity violated

ADR-30: UI STATE ISOLATION RULE
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — React layer is common violation point for INV-3

PROHIBITED PATTERNS IN UI:

  ❌ Local useState storing RoutingDecision derived values
  ❌ AnalyticsPanel computing metrics locally (outside MetricsService)
  ❌ useEffect caching Router results between renders
  ❌ Component-level "recent decisions" accumulation

REQUIRED PATTERN:

  UI component must treat KernelSnapshot as:
    → immutable snapshot stream arriving via EventBus
    → source for display only, never for logic

  ALL derived state must come from:
    → computeMetrics(eventLog) [ADR-24]
    → NOT local component state

  REACT RULE:
    useMemo(() => computeMetrics(eventLog), [eventLog])  // OK
    useState(computeMetrics(...))  // FORBIDDEN — stale on next tick

WHY:
  React local state accumulates across renders → hidden temporal bias
  Equivalent to EphemeralState violation (ADR-16) in UI layer

═══════════════════════════════════════════════════════════
ADR-31: INV-1 NUMERIC STABILIZATION (SIMPLEX PROJECTION)
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — floating point drift will cause intermittent INV-1 failures

CURRENT RISK:
  weights.ttft + weights.tps + weights.reliability = 1.0
  After many incremental updates: sum = 0.9999999... or 1.0000001...
  → INV-1 check fails intermittently under load

REQUIRED — apply simplex projection BEFORE every commit:

  function projectToSimplex(w: RouterWeights): RouterWeights {
    const sum = w.ttft + w.tps + w.reliability;
    return {
      ttft:        w.ttft / sum,
      tps:         w.tps / sum,
      reliability: w.reliability / sum
    };
  }

  RULE:
    → projectToSimplex() is called by Invariant Guard (ADR-01.B)
    → BEFORE INV-1 validation
    → BEFORE state commit
    → operation order must be deterministic (ttft → tps → reliability always)

  RESULT:
    → INV-1 becomes unconditionally satisfied after projection
    → "error correction" state eliminated
    → no more "auto-fix after violation" pattern

═══════════════════════════════════════════════════════════
ADR-32: BACKPRESSURE SNAPSHOT FREEZE (QUEUE TICK BINDING)
═══════════════════════════════════════════════════════════
STATUS: REQUIRED — routing under load becomes time-dependent without this

CURRENT RISK:
  Request enters ChatService queue at tick t0
  Kernel state evolves: t1, t2, t3...
  Request executes at tick t5 using snapshot[t5]
  → routing decision uses DIFFERENT snapshot than at enqueue time
  → INV-3 violated: same request produces different routing under load

FIX — Snapshot binding at enqueue time:

  When request enters ChatService queue:
    request.boundSnapshot = kernel.getSnapshot()  // snapshot at t_enqueue
    request.boundTick = kernel.currentTick

  When request executes:
    route(context, request.boundSnapshot, learningSignals[t_execute - 1])
    // NOT kernel.getSnapshot() at execution time

  GUARANTEE:
    → routing decision is independent of queue wait time
    → identical requests produce identical routing regardless of load
    → INV-3 holds under arbitrarily high load
